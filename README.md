# Installations
We recommend cloning the git repo and creating a `conda` environment with the required dependencies from the `environment.yml` file
```
git clone https://github.com/afselim0/structure-thru-time
conda env create -f environment.yml
conda activate STT
```

# Basic Usage
The main input to **sturcture-thru-time** a directory with a list of [tree sequences](https://tskit.dev/software/tskit.html) format. They should all end with the suffix **.trees**. If the tree sequences are samples from a posterior (singer), each sample should be saved as `{ContigID}_{PosteriorSample}.trees`

To run STT:
```
cd utils
snakemake STT --configfile PATH/TO/CONFIG.yaml --cores all
```
Parameters are passed to the snakemake in a `--config.yaml` as shown above. Refer to `data/empirical_runs/` for examples on some config files. 
THe pipeline in `utils/snakefile` is a general pipeline that runs STT along with any other necessary steps. Currently, it can:
1. Simulate trees based on a `.demes` file and run STT on them.
2. Infer trees given by taking in vcfs generated by the simulated trees. Supports: `[tsinfer, relate, SINGER]`.
3. Run STT directly on trees already inferred from empirical data.

Running STT itself generates the following files:
1. Inferred probability density function of pairwise coalescent rates (this is the step that takes most time)
2. Inferred pairwise coalescent rates as a function of time + plots of rates over time
3. Inferred embeddings of samples over time + plots of embeddings
4. Performance evaluation data + plots

# Interactive embedding & sharing it
Each STT run writes a `launch_dash*.sh` script in its `plots/` directory. Run it to open an interactive [Dash](https://dash.plotly.com/) app (time slider over the embedding + an input-vs-reconstructed rates panel):
```
bash results/<run>/plots/launch_dash<TAG>.sh   # open the printed http://127.0.0.1:<port> URL
```

To send the interactive plot to a collaborator who doesn't have this repo, package it into a self-contained zip (the app, its data, a pinned `environment.yml`, a `run.sh`, and a README) with `utils/bundle_dash.py`. The easiest way is to point it at the run's config:
```
cd utils
python bundle_dash.py --config PATH/TO/CONFIG.yaml   # writes <output_path>/plots/dash_bundle<TAG>.zip
```
or run it through Snakemake (same output path):
```
snakemake bundle_dash --configfile PATH/TO/CONFIG.yaml --cores 1
```
The collaborator then unzips, `conda env create -f environment.yml && conda activate stt_dash`, and runs `./run.sh`. `bundle_dash.py` also accepts explicit `--rates/--colors/...` paths (and `--covariances` for uncertainty ellipses) for embeddings produced outside the pipeline; explicit flags override config-derived values. Bundle size tracks the rates parquets, so for many-sample runs omit `--rates`/`--reconstructed_rates` (or use a sample subset) to keep it small.

# Snakemake modes
To run a particular mode of the pipeline, specify the rule associated with that mode. For each mode, certain input parameters are relevant

## STT only
To run STT on trees that are already inferred, use the rule `snakemake STT` **Note: Make sure that the directory that contains the trees has a file with the name `trees_ready.txt`**

**Note: Computational time scales linearly with max_time and number of internal nodes in a given tree sequence. Memory scales linearly with num_timepoints**

The following are parameters that can be passed to `--config` and that affect downstream results
| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **version**              | Version of method                                                            | None           |
| **trees_dir**            | Path to a directory containing `.trees` files                                | ALL            |
| **output_path**          | Path to the output directory                                                 | ALL            |
| **num_posterior_samples**| Number of posterior samples (if `singer` was used for inference)             | ALL            |
| **pops**                 | Subset of populations to draw samples from (default: all)                    | ALL            |
| **n_samples_per_pop**    | Number of samples per population (default: all)                              | ALL            |
| **max_time**             | Maximum time used for computing PDFs, rates, and embeddings                  | Coalescent PDF |
| **n_timepoints**         | Number of equally spaced time points from `t = 0` to `max_time`              | Coalescent PDF |
| **fraction_samples**     | Fraction of samples used per contig (default: 1.0)                           | Coalescent PDF |
| **min_window_size**      | Minimum window size for local regression when computing rates                | Rates          |
| **max_window_size**      | Maximum window size for local regression when computing rates (linear growth)| Rates          |
| **N_min**                | Population size for two samples at zero distance                             | Embeddings     |
| **N_max**                | Population size for two samples at max distance                              | Embeddings     |
| **l1**                   | list of l1 penalties, comma seperated, on (first, second, ...) derivatives   | Embeddings     |
| **l2**                   | list of l2 penalties, comma seperated, on (first, second, ...) derivatives   | Embeddings     |
| **max_rate_plot**        | Maximum rate (y-axis) in rate plots (for easy comparisons)                   | Plotting       |
| **min_time**             | Minimum time shown in plots                                                  | Plotting       |
| **embeddings_plot_lims** | Limits of X and Y axes in embeddings plots (for easy comparisons)            | Plotting       |
| **pop_labels**           | Path to population labels for each sample                                    | Plotting       |
| **pop_colors**           | Path to population colors                                                    | Plotting       |

## Simulations
To simulate a set of tree sequences given a demography, use the rule `snakemake sim`. This rule also runs STT on the true rates from the demes file.
TO simulate tree sequences and then run STT on them, use the rule `snakemake sim_STT`.
For a given demogarphy, a set of independent contig of the same size are simulated with a constant mutation and recombination rate.

| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **demes_file_path**      | Path to the demes file to simulate                                           | All.           |
| **num_contigs**          | Number of independent contigs to simulate                                    | All.           |
| **contig_length**        | Number of base pairs in each contig                                          | All.           |
| **n_sim_per_pop**        | Number of samples to simualte per population                                 | All.           |
| **mutation_rate**        | Constant mutation rate                                                       | All.           |
| **recombination_rate**   | Constant recombination rate                                                  | All.           |

## Inference
To infer trees from a set of simulated vcfsy, use the rule `snakemake infer`.
TO infer tree sequences and then run STT on them, use the rule `snakemake infer_STT`.
If you're running this using relate or singer make sure to reference the correct version of relate/singer in the file `utils/infer_trees.py`. Recommended to run this on linux.

| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **infer_method**         | Inference method from (tsinfer, relate, singer)                              | None           |
| **vcf_dir**              | Directory containing vcfs from simulated trees                               | All.           |
| **num_contigs**          | Number of independent contigs simualted.                                     | All.           |
| **contig_length**        | Number of base pairs in each contig                                          | All.           |
| **burnin**               | MCMC burnin (SINGER).                                                        | All.           |
| **num_posterior_samples**| number of posterior MCMC samples (SINGER)                                    | All.           |
| **thinning_interval**    | MCMC thinning interval (SINGER)                                              | All.           |
