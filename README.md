# Installations
We recommend cloning the git repo and creating a `conda` environment with the required dependencies from the `environment.yml` file
```
git clone https://github.com/afselim0/structure-thru-time
cd structure-thru-time
conda env create -f environment.yml
conda activate CoaSTT_env
bash utils/misc_utils/install_libstdcxx_hook.sh   # once, then re-activate the env
```

The last step installs a conda activation hook that puts the environment's own
`libstdc++` ahead of the system one. It is only strictly needed on older Linux
distributions (RHEL/CentOS 8 and similar, e.g. midway3), where the system
`libstdc++` predates `GLIBCXX_3.4.29`: several pip wheels here are manylinux
builds that would otherwise load it and make a later `import numpy` fail with
`GLIBCXX_3.4.29 not found` — typically surfacing as a `snakemake` crash even
though `python -c "import numpy"` works. Running it on a modern distribution is
harmless. See `utils/misc_utils/install_libstdcxx_hook.sh` for the full story.

# Reproducing everything from a fresh clone

Five steps, in order. Each reads the previous one's output, and everything lives
under `utils/runs/`. The drivers are self-anchoring, so they can be invoked from
any directory.

### 1. Install the environment
As under [Installations](#installations):
```
conda env create -f environment.yml
conda activate CoaSTT_env
bash utils/misc_utils/install_libstdcxx_hook.sh   # once, then re-activate the env
```

### 2. Set up `slurm.yaml`, if you are running on a cluster
Skip this step to run everything on the local machine.

The run scripts take a `--slurm` flag, and read your account, partition and
environment from a config file you create once:
```
cd utils/runs/CoaSTT_runs
cp slurm.yaml.example slurm.yaml
$EDITOR slurm.yaml
```
`slurm.yaml.example` documents every key. At minimum set `account`, `partition`
and `conda_env` (the path to the environment created in step 1); `conda_sh`,
`pre_activate`, `sbatch_extra`, `log_dir` and `workdir_root` cover the rest of
what a site may need. `slurm.yaml` is gitignored, so your own settings stay
local. Nothing else in the repo hard-codes a cluster.

### 3. Run the CoaSTT pipeline
This is the expensive step — days of compute for the full set. Each run is
driven by one config in `data/configs/{sim,app}_configs/` and one matching
script in `utils/runs/CoaSTT_runs/{sim,app}_runs/`.
```
bash utils/runs/generate_sim_results.sh            # -> results/outputs/simulations/
bash utils/runs/generate_app_results.sh            # -> results/outputs/empirical/

bash utils/runs/generate_sim_results.sh --slurm    # the same, as SLURM jobs
bash utils/runs/generate_app_results.sh --slurm
```
Run the sim results before the app results: the SINGER runs infer trees from the
simulated ones. Add `-n` for a dry run — of snakemake locally, or of the
submission plan under `--slurm`.

To run a single case, invoke its script directly; the same flags apply:
```
bash utils/runs/CoaSTT_runs/sim_runs/complex_4_pops.sh
bash utils/runs/CoaSTT_runs/sim_runs/complex_4_pops.sh --slurm
```

### 4. Prepare the figure data
```
bash utils/runs/prepare_all_figure_data.sh         # -> results/figure_data/
```
Always local: these scripts are light next to the runs that produced their
inputs. Each turns raw outputs into the tidy tables one figure is drawn from,
and a report of which succeeded and which failed is written to
`utils/runs/figure_data.txt`. A figure whose run is not on this machine fails
with `missing run: <path>`, and the driver carries on with the rest. The tables
are checked in, so this step is only needed after a run changes. Per-figure
details are in `results/figure_data/README.md`.

### 5. Draw the figures
```
bash utils/runs/generate_sim_figures.sh            # -> results/figures/sim_figs/
bash utils/runs/generate_app_figures.sh            # -> results/figures/app_figs/
```
Also always local. Drawing is deliberately split from preparation: the plotting
scripts read `results/figure_data/` only, and never touch `results/outputs/`,
run the optimizer, or align anything themselves. Since the tables are checked
in, these two can be run on a fresh clone without steps 3 and 4.

Figures are written as PDFs; PNG intermediates go to the gitignored
`*_figs_png/` directories. Rendering the 3D embedding panels needs Chrome for
kaleido — on a machine without one, run
`python -c "from kaleido import get_chrome_sync; print(get_chrome_sync())"` once.

# Basic Usage
The main input to **CoaSTT** a directory with a list of [tree sequences](https://tskit.dev/software/tskit.html) (inferred or simulated). They should all end with the suffix **.trees**. If the tree sequences are samples from a posterior (singer), each posterior sample should be saved in an different directory. **CoaSTT** can be run on each posterior sample one at a time.

To run CoaSTT:
```
cd utils
snakemake STT --configfile PATH/TO/CONFIG.yaml --cores all
```
Parameters are passed to the snakemake through a config file. Refer to `data/configs/sim_configs/` for examples on some config files.
The pipeline in `utils/snakefile` is a general pipeline that runs CoaSTT along with any other necessary steps. Currently, it can:
1. Simulate trees based on a `.demes` file and run CoaSTT on them.
2. Infer trees given by taking in vcfs generated by the simulated trees. Supports: `[tsinfer, relate, SINGER]`.
3. Run CoaSTT directly on trees already inferred from empirical data.

Running CoaSTT itself generates the following files:
1. Inferred probability density function of pairwise coalescent times (this is the step that takes most time)
2. Inferred pairwise coalescent rates as a function of time + plots of rates over time
3. Inferred latent embeddings of samples over time + plots of embeddings
4. Performance evaluation data + plots

# Interactive embedding & sharing it
Each CoaSTT run writes a `launch_dash*.sh` script in its `plots/` directory. Run it to open an interactive [Dash](https://dash.plotly.com/) app (time slider over the embedding + an input-vs-reconstructed rates panel):
```
bash results/outputs/simulations/<run>/plots/launch_dash<TAG>.sh   # open the printed http://127.0.0.1:<port> URL
```

To send the interactive plot to a collaborator who doesn't have this repo, package it into a self-contained zip (the app, its data, a pinned `environment.yml`, a `run.sh`, and a README) with `utils/snakemake_utils/bundle_dash.py`. The easiest way is to point it at the run's config:
```
cd utils
python snakemake_utils/bundle_dash.py --config PATH/TO/CONFIG.yaml   # writes <output_path>/plots/dash_bundle<TAG>.zip
```
or run it through Snakemake (same output path):
```
snakemake bundle_dash --configfile PATH/TO/CONFIG.yaml --cores 1
```
The collaborator then unzips, `conda env create -f environment.yml && conda activate stt_dash`, and runs `./run.sh`. `bundle_dash.py` also accepts explicit `--rates/--colors/...` paths (and `--covariances` for uncertainty ellipses) for embeddings produced outside the pipeline; explicit flags override config-derived values.

Bundle size is dominated by the rate parquets (they grow ~quadratically in sample count — e.g. ~3 GB for a 332-sample run). To keep bundles shareable, `bundle_dash.py` does two things by default:
1. **Auto-thins** the rate parquets' timepoint columns down to ~the embeddings timepoint count (`--rates-time-stride auto`). This is near-lossless — the dash app snaps the time slider to the nearest rate column and can't resolve finer than the embeddings grid — and shrinks a 332-sample `rates.parquet` ~10× (2.5 GB → ~0.2 GB). Use `--rates-time-stride N` for an explicit divisor, or `1` to disable.
2. **Omits** the rate parquets entirely (with a warning, embeddings-only bundle) if their thinned combined size still exceeds 500 MB. Pass `--force-rates-export` to include them anyway, or `--max-rates-mb N` to change the threshold.

The `snakemake bundle_dash` rule applies the same defaults; set `rates_time_stride: N` in a config to override.

To run a particular mode of the pipeline, specify the rule associated with that mode. For each mode, certain input parameters are relevant

## Admixture extension
If some of your samples are admixed, CoaSTT can additionally infer local ancestry and repeat the whole rates/embeddings/plotting pipeline once per reference (ancestry) population — on top of the regular genome-wide run. This is activated automatically whenever `snakemake STT` (or `STT_sim`/`STT_infer`) is run with `admixed_pops` set in the config; no separate rule or command is needed.

Pipeline, in order:
1. The regular genome-wide CoaSTT pipeline runs as usual (counts, PDF, rates, embeddings).
2. `infer_local_ancestry.py` determines local ancestry along the genome for samples in `admixed_pops`, using samples in `reference_pops` as reference panels. The method is selected with `LAI_method` (see below).
3. `compute_pdf.py` additionally computes a per-reference-population coalescent-time PDF (using the local ancestry calls from step 2).
4. The rates/embeddings/plotting pipeline is repeated once per reference population, using each population's own PDF and (ancestry-filtered) sample labels.

| Parameter                          | Description                                                                                          | Affected files |
|-------------------------------------|--------------------------------------------------------------------------------------------------------|----------------|
| **admixed_pops**                   | List of population names (as they appear in `pop_labels`) to treat as admixed. Setting this activates admixture mode. | ALL (admixture) |
| **reference_pops**                 | The reference/ancestry panels. Either a plain list of population names, or named **composite** panels built from per-population individual counts (see below). If omitted, defaults to every population in `pop_labels` other than `admixed_pops` (and, if `pops` restricts the run, further limited to that set) | ALL (admixture) |
| **significant_ancestry_threshold** | Minimum genome-wide ancestry proportion (per reference population) an admixed sample needs to be kept in that reference population's analysis (default: `0.05`) | Local ancestry |
| **LAI_method**                     | Local ancestry inference method: `RFmix` (default), `GNN`, or `True` | Local ancestry |

### Reference panels (`reference_pops`)

Three spellings, in increasing order of control:

```yaml
# 1. omitted — every non-admixed population becomes a panel, using all its samples
# 2. a plain list — one panel per named population, using all its samples
reference_pops: [Eastern, Central, Western]

# 3. composite panels — each panel is a named group drawn from one or more
#    populations, at a chosen number of individuals per population
reference_pops:
  EastCentral:
    Eastern: 5
    Central: 5
  West:
    Western: 10
```

The composite form exists to make panels **size-matched**. Populations rarely have equal
sample counts, so a panel that takes "all of Eastern" against "all of Western" is unbalanced
before inference starts. The example above gives two panels of 10 individuals (20 haplotypes)
each.

- **Counts are diploid individuals.** Both haplotypes of each chosen individual enter the panel.
- **Selection is deterministic and seedless**: the first *n* individuals by `individual_id`.
  This is a *systematic* rather than random sample — if `individual_id` order correlates with
  anything (accession order, sequencing batch), so does the panel. Reorder or renumber
  `pop_labels.csv` to choose a different subset.
- **Asking for more individuals than a population has is an error**, not a silent truncation:
  the point of the counts is balance, and a quiet shortfall would defeat it invisibly.
- **Panels must be disjoint** — no population may appear in two groups. `GNN` takes an argmax
  over the panels and `RFmix` assigns one label per individual, so overlapping panels are
  undefined rather than merely redundant.
- The group name becomes the ancestry label everywhere downstream (the `<label>_prop` column,
  the `ancestry_STT/<method>/<label>/` directory, plot legends), so it must match
  `[A-Za-z0-9_.-]+` and must not end in `_prop`.
- The two forms can be mixed: a group whose value is left empty means "all samples of the
  population with that name".
- **Composite panels are incompatible with `LAI_method: True`**, which is rejected at parse
  time: ground-truth labels come from msprime census nodes and are always atomic deme names.

Whatever form is used, `{output_path}/LAI/{LAI_method}/reference_panels.csv` records exactly
which samples ended up in which panel — including what the default resolved to. Checking balance
is one line:

```bash
python -c "import pandas as pd; print(pd.read_csv('.../reference_panels.csv').groupby(['ancestry_label','source_population']).size())"
```

> Changing the set of panel *names* leaves the previous run's `ancestry_STT/<method>/<old_label>/`
> directories on disk, and they are rediscovered by globbing. Remove
> `{output_path}/ancestry_STT/{LAI_method}/` when the label set changes.

### Local ancestry methods (`LAI_method`)

| Value    | Source | Behaviour |
|----------|--------|-----------|
| `RFmix`  | `src/LocalAncestryRFmix.py` | Runs RFMix2 on a VCF exported from each contig's tree sequence. The default. |
| `GNN`    | `src/LocalAncestryGNN.py`   | Assigns ancestry per local tree via genealogical nearest neighbours (argmax over reference groups). Uses the genealogy directly, so no VCF export or external binary is needed. |
| `True`   | `utils/snakemake_utils/simulate_trees.py` (`compute_true_local_ancestry`) | Uses the ground-truth calls recorded from the msprime census nodes at simulation time. Nothing is inferred — useful as an upper bound when benchmarking `RFmix`/`GNN`. |

`LAI_method: True` is only valid for simulated data: it requires `demes_file_path` to be set and the run to simulate its own trees (no external `trees_dir`). Both conditions are checked when the Snakefile is parsed. It also requires a demography with a positive `admix_time` in `pop_labels.csv`, since that is what makes `simulate_trees.py` emit the census-based calls.

Note that in YAML, an unquoted `LAI_method: True` parses as a boolean; the Snakefile coerces it back to the string `"True"`, so both `True` and `"True"` work.

Notes:
- If `pops` is also set (restricting the whole run to a subset of populations), `admixed_pops` — and the source populations of `reference_pops` if given explicitly — must be subsets of `pops`.
- `RFmix` inference always runs single-threaded regardless of `num_threads`, since parallelizing it has been observed to be slower, not faster. `GNN` and `True` are parallelized across contigs using `num_threads`.
- Outputs are namespaced by method, so runs using different methods can share one `output_path` without overwriting each other:
  - `{output_path}/LAI/{LAI_method}/` — per-contig local ancestry calls, plus `total_ancestry_proportions.parquet` and `reference_panels.csv` (which samples formed each panel).
  - `{output_path}/ancestry_STT/{LAI_method}/{reference_pop}/{data,plots}/` — one subdirectory per reference population, mirroring the layout of the genome-wide `data/`/`plots/` directories (same rates/embeddings/plot filenames, just nested per method and population).
- Ground-truth calls are always written to `{output_path}/LAI/True/` during simulation whenever the demography is admixed, regardless of which `LAI_method` the run uses — so they remain available as a reference for comparison against `RFmix`/`GNN` output.

## Simulations
To simulate a set of tree sequences given a demography, use the rule `snakemake sim`. This rule also runs CoaSTT on the true rates from the demes file.
To simulate tree sequences and then run CoaSTT on them, use the rule `snakemake sim_STT`.
For a given demography, a set of independent contig of the same size are simulated with a constant mutation and recombination rate.

| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **demes_file_path**      | Path to the demes file to simulate                                           | All.           |
| **num_contigs**          | Number of independent contigs to simulate                                    | All.           |
| **contig_length**        | Number of base pairs in each contig                                          | All.           |
| **n_sim_per_pop**        | Number of samples to simualte per population                                 | All.           |
| **mutation_rate**        | Constant mutation rate                                                       | All.           |
| **recombination_rate**   | Constant recombination rate                                                  | All.           |

## Inference
To infer trees from a set of simulated vcfs, use the rule `snakemake infer`.
To infer tree sequences and then run CoaSTT on them, use the rule `snakemake infer_STT`.
If you're running this using relate or singer make sure to reference the correct version of relate/singer in the file `utils/snakemake_utils/infer_trees.py`. Recommended to run this on linux.

| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **infer_method**         | Inference method from (tsinfer, relate, singer)                              | None           |
| **vcf_dir**              | Directory containing vcfs from simulated trees                               | All.           |
| **num_contigs**          | Number of independent contigs simulated.                                     | All.           |
| **contig_length**        | Number of base pairs in each contig                                          | All.           |
| **burnin**               | MCMC burnin (SINGER).                                                        | All.           |
| **num_posterior_samples**| number of posterior MCMC samples (SINGER)                                    | All.           |
| **thinning_interval**    | MCMC thinning interval (SINGER)                                              | All.           |
