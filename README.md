# Installations
We recommend cloning the git repo and creating a `conda` environment with the required dependencies from the `environment.yml` file
```
git clone https://github.com/afselim0/structure-thru-time
conda env create -f environment.yml
conda activate STT
```

# Basic Usage
The main input to **CoaSTT** a directory with a list of [tree sequences](https://tskit.dev/software/tskit.html) format. They should all end with the suffix **.trees**. If the tree sequences are samples from a posterior (singer), each sample should be saved as `{ContigID}_{PosteriorSample}.trees`

To run CoaSTT:
```
cd utils
snakemake STT --configfile PATH/TO/CONFIG.yaml --cores all
```
Parameters are passed to the snakemake in a `--config.yaml` as shown above. Refer to `data/empirical_runs/` for examples on some config files. 
THe pipeline in `utils/snakefile` is a general pipeline that runs CoaSTT along with any other necessary steps. Currently, it can:
1. Simulate trees based on a `.demes` file and run CoaSTT on them.
2. Infer trees given by taking in vcfs generated by the simulated trees. Supports: `[tsinfer, relate, SINGER]`.
3. Run CoaSTT directly on trees already inferred from empirical data.

Running CoaSTT itself generates the following files:
1. Inferred probability density function of pairwise coalescent rates (this is the step that takes most time)
2. Inferred pairwise coalescent rates as a function of time + plots of rates over time
3. Inferred embeddings of samples over time + plots of embeddings
4. Performance evaluation data + plots

# Interactive embedding & sharing it
Each CoaSTT run writes a `launch_dash*.sh` script in its `plots/` directory. Run it to open an interactive [Dash](https://dash.plotly.com/) app (time slider over the embedding + an input-vs-reconstructed rates panel):
```
bash results/<run>/plots/launch_dash<TAG>.sh   # open the printed http://127.0.0.1:<port> URL
```

To send the interactive plot to a collaborator who doesn't have this repo, package it into a self-contained zip (the app, its data, a pinned `environment.yml`, a `run.sh`, and a README) with `utils/bundle_dash.py`. The easiest way is to point it at the run's config:
```
cd utils
python bundle_dash.py --config PATH/TO/CONFIG.yaml   # writes <output_path>/plots/dash_bundle<TAG>.zip
```
or run it through Snakemake (same output path):
```
snakemake bundle_dash --configfile PATH/TO/CONFIG.yaml --cores 1
```
The collaborator then unzips, `conda env create -f environment.yml && conda activate stt_dash`, and runs `./run.sh`. `bundle_dash.py` also accepts explicit `--rates/--colors/...` paths (and `--covariances` for uncertainty ellipses) for embeddings produced outside the pipeline; explicit flags override config-derived values.

Bundle size is dominated by the rate parquets (they grow ~quadratically in sample count — e.g. ~3 GB for a 332-sample run). To keep bundles shareable, `bundle_dash.py` does two things by default:
1. **Auto-thins** the rate parquets' timepoint columns down to ~the embeddings timepoint count (`--rates-time-stride auto`). This is near-lossless — the dash app snaps the time slider to the nearest rate column and can't resolve finer than the embeddings grid — and shrinks a 332-sample `rates.parquet` ~10× (2.5 GB → ~0.2 GB). Use `--rates-time-stride N` for an explicit divisor, or `1` to disable.
2. **Omits** the rate parquets entirely (with a warning, embeddings-only bundle) if their thinned combined size still exceeds 500 MB. Pass `--force-rates-export` to include them anyway, or `--max-rates-mb N` to change the threshold.

The `snakemake bundle_dash` rule applies the same defaults; set `rates_time_stride: N` in a config to override.

# Snakemake modes
To run a particular mode of the pipeline, specify the rule associated with that mode. For each mode, certain input parameters are relevant

## CoaSTT only
To run CoaSTT on trees that are already inferred, use the rule `snakemake STT` **Note: Make sure that the directory that contains the trees has a file with the name `trees_ready.txt`**

**Note: Computational time scales linearly with max_time and number of internal nodes in a given tree sequence. Memory scales linearly with num_timepoints**

The following are parameters that can be passed to `--config` and that affect downstream results
| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **version**              | Version of method                                                            | None           |
| **trees_dir**            | Path to a directory containing `.trees` files                                | ALL            |
| **output_path**          | Path to the output directory                                                 | ALL            |
| **num_posterior_samples**| Number of posterior samples (if `singer` was used for inference)             | ALL            |
| **pops**                 | Subset of populations to draw samples from (default: all)                    | ALL            |
| **n_samples_per_pop**    | Number of samples per population (default: all)                              | ALL            |
| **max_time**             | Maximum time used for computing PDFs, rates, and embeddings                  | Coalescent PDF |
| **n_timepoints**         | Number of equally spaced time points from `t = 0` to `max_time`              | Coalescent PDF |
| **fraction_samples**     | Fraction of samples used per contig (default: 1.0)                           | Coalescent PDF |
| **min_window_size**      | Minimum window size for local regression when computing rates                | Rates          |
| **max_window_size**      | Maximum window size for local regression when computing rates (linear growth)| Rates          |
| **per_haplotype**        | If `true`, rates/embeddings/plots are per-haplotype rather than per-individual (default: `false`) | Rates, Embeddings, Plotting |
| **compute_variance**     | If `true`, estimate standard errors of rates via block-jackknife (default: `true`) | Rates     |
| **N_min**                | Population size for two samples at zero distance                             | Embeddings     |
| **N_max**                | Population size for two samples at max distance                              | Embeddings     |
| **p**                    | Exponent of the link function (default: 1)                                  | Embeddings     |
| **link**                 | Link function relating latent distance to coalescent rate (default: `inverse_distance`) | Embeddings |
| **l1**                   | list of l1 penalties, comma seperated, on (first, second, ...) derivatives   | Embeddings     |
| **l2**                   | list of l2 penalties, comma seperated, on (first, second, ...) derivatives   | Embeddings     |
| **n_components**         | Number of latent dimensions for embeddings (default: 2)                     | Embeddings     |
| **n_timepoints_emb**     | Number of timepoints used when computing/plotting embeddings (default: `n_timepoints`) | Embeddings, Plotting |
| **seeds**                | List of seeds for `snakemake STT_replicates` (repeated optimizations with different random seeds; default: none) | Embeddings |
| **rates_time_stride**    | Thinning stride for rate-parquet timepoints when bundling a dash app (`"auto"`\|`N`\|`1`, default: `auto`) | dash bundle |
| **max_rate_plot**        | Maximum rate (y-axis) in rate plots (for easy comparisons)                   | Plotting       |
| **min_time**             | Minimum time shown in plots                                                  | Plotting       |
| **embeddings_plot_lims** | Limits of X and Y axes in embeddings plots (for easy comparisons)            | Plotting       |
| **embeddings_max_time**  | Maximum time shown in embeddings plots (default: `max_time`)                 | Plotting       |
| **time_scale**           | Axis scale for time in plots (`linear` or `log`, default: `linear`)          | Plotting       |
| **pop_labels**           | Path to population labels for each sample                                    | Plotting       |
| **pop_colors**           | Path to population colors                                                    | Plotting       |

## Admixture extension
If some of your samples are admixed, CoaSTT can additionally infer local ancestry and repeat the whole rates/embeddings/plotting pipeline once per reference (ancestry) population — on top of the regular genome-wide run. This is activated automatically whenever `snakemake STT` (or `STT_sim`/`STT_infer`) is run with `admixed_pops` set in the config; no separate rule or command is needed.

Pipeline, in order:
1. The regular genome-wide CoaSTT pipeline runs as usual (counts, PDF, rates, embeddings).
2. `infer_local_ancestry.py` runs RFMix2 to infer local ancestry along the genome for samples in `admixed_pops`, using samples in `reference_pops` as reference panels.
3. `compute_pdf.py` additionally computes a per-reference-population coalescent-time PDF (using the local ancestry calls from step 2).
4. The rates/embeddings/plotting pipeline is repeated once per reference population, using each population's own PDF and (ancestry-filtered) sample labels.

| Parameter                          | Description                                                                                          | Affected files |
|-------------------------------------|--------------------------------------------------------------------------------------------------------|----------------|
| **admixed_pops**                   | List of population names (as they appear in `pop_labels`) to treat as admixed. Setting this activates admixture mode. | ALL (admixture) |
| **reference_pops**                 | List of population names to use as reference/ancestry labels. If omitted, defaults to every population in `pop_labels` other than `admixed_pops` (and, if `pops` restricts the run, further limited to that set) | ALL (admixture) |
| **significant_ancestry_threshold** | Minimum genome-wide ancestry proportion (per reference population) an admixed sample needs to be kept in that reference population's analysis (default: `0.05`) | Local ancestry |

Notes:
- If `pops` is also set (restricting the whole run to a subset of populations), `admixed_pops` — and `reference_pops` if given explicitly — must be subsets of `pops`.
- Local ancestry inference (`infer_local_ancestry`) always runs single-threaded regardless of `num_threads`, since parallelizing it has been observed to be slower, not faster.
- Outputs are written under `{output_path}/LAI/` (per-contig local ancestry calls) and `{output_path}/ancestry_STT/{reference_pop}/{data,plot}/` (one subdirectory per reference population, mirroring the layout of the genome-wide `data/`/`plots/` directories — same rates/embeddings/plot filenames, just one level down per population).

## Simulations
To simulate a set of tree sequences given a demography, use the rule `snakemake sim`. This rule also runs CoaSTT on the true rates from the demes file.
TO simulate tree sequences and then run CoaSTT on them, use the rule `snakemake sim_STT`.
For a given demogarphy, a set of independent contig of the same size are simulated with a constant mutation and recombination rate.

| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **demes_file_path**      | Path to the demes file to simulate                                           | All.           |
| **num_contigs**          | Number of independent contigs to simulate                                    | All.           |
| **contig_length**        | Number of base pairs in each contig                                          | All.           |
| **n_sim_per_pop**        | Number of samples to simualte per population                                 | All.           |
| **mutation_rate**        | Constant mutation rate                                                       | All.           |
| **recombination_rate**   | Constant recombination rate                                                  | All.           |

## Inference
To infer trees from a set of simulated vcfsy, use the rule `snakemake infer`.
TO infer tree sequences and then run CoaSTT on them, use the rule `snakemake infer_STT`.
If you're running this using relate or singer make sure to reference the correct version of relate/singer in the file `utils/infer_trees.py`. Recommended to run this on linux.

| Parameter                | Description                                                                  | Affected files |
|--------------------------|------------------------------------------------------------------------------|----------------|
| **num_threads**          | Number of threads for parallel pdf computation (too much is too slow!)       | None           |
| **infer_method**         | Inference method from (tsinfer, relate, singer)                              | None           |
| **vcf_dir**              | Directory containing vcfs from simulated trees                               | All.           |
| **num_contigs**          | Number of independent contigs simualted.                                     | All.           |
| **contig_length**        | Number of base pairs in each contig                                          | All.           |
| **burnin**               | MCMC burnin (SINGER).                                                        | All.           |
| **num_posterior_samples**| number of posterior MCMC samples (SINGER)                                    | All.           |
| **thinning_interval**    | MCMC thinning interval (SINGER)                                              | All.           |
